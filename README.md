Тестовый сервис отслеживания посылок.

Проект представляет собой бэкенд-сервис для автоматизации логистики и отслеживания статусов отправлений. 
Вся логика хранения данных, изменения статусов и валидации бизнес-правил реализована на уровне базы данных и покрыта интеграционными тестами.

### Реализованный функционал (Бизнес-логика)
1.Регистрация отправлений: Создание новой записи в БД с автоматическим присвоением уникального трек-номера (равного ID записи) и статусом `зарегистрирована`.

2.Управление жизненным циклом: Реализован конечный автомат для статусов посылки: `зарегистрирована` ➡️ `отправлена` ➡️ `доставлена`.

3.Валидация бизнес-правил: Изменение адреса доставки или полное удаление посылки из системы жестко заблокированы, если посылка уже сменила статус и была отправлена/доставлена.

4.Выгрузка данных: Получение актуального списка всех отправлений конкретного клиента.

5.Автоматическое тестирование: Написан пакет тестов для сквозной проверки корректности работы функций с базой данных.

### 📐 Архитектура данных (Схема таблицы `packages`)

Логика хранения реализована через структуру со следующими ключевыми полями:

* `id` (INT, Primary Key) — уникальный идентификатор и трек-номер посылки.
* 
* `client_id` (INT) — идентификатор клиента-получателя.
* 
* `address` (TEXT) — адрес доставки (доступен для редактирования только в статусе `зарегистрирована`).
* 
* `status` (VARCHAR) — текущий статус (`зарегистрирована`, `отправлена`, `доставлена`).

---

###  Примеры ключевых SQL-операций в проекте

1. Безопасное обновление адреса с проверкой статуса

*Бизнес-правило: менять адрес можно только у неотправленных посылок.*
```sql
UPDATE packages 
SET address = 'Новый адрес, д. 10' 
WHERE id = 1042 AND status = 'зарегистрирована';
```

2. Безопасное удаление посылки

```sql
DELETE FROM packages 
WHERE id = 1042 AND status = 'зарегистрирована';
```

### Тестирование (Database Integration Tests)

В проекте реализованы тесты, которые разворачивают тестовую БД, наполняют её фиктивными данными и проверяют:
1. Что при создании посылки статус железно выставляется в `зарегистрирована`.
2. Что трек-номер совпадает с сгенерированным `id`.
3. Что систему нельзя обмануть и удалить посылку со статусом `отправлена`.
