# Сервис отслеживания посылок на Go (SQLite & Интеграционное тестирование) 

Программный модуль на языке **Go** для автоматизированного сервиса учета и отслеживания посылок. Приложение построено по паттерну Repository: бизнес-логика (`ParcelService`) отделена от слоя работы с данными (`ParcelStore`), а вся информация хранится в локальной базе данных **SQLite**.

## Схема базы данных (`tracker.db`)
Вся информация о посылках хранится в реляционной таблице `parcel` со следующей структурой:
*   `number` (INTEGER, AUTOINCREMENT) — уникальный номер посылки (трек-номер).
*   `client` (INTEGER) — идентификатор клиента-владельца.
*   `status` (TEXT) — текущий статус посылки (`registered`, `sent`, `delivered`).
*   `address` (TEXT) — адрес доставки отправления.
*   `created_at` (TEXT) — дата и время регистрации посылки в системе.

---

## Архитектура и жизненный цикл посылки

Приложение строго контролирует бизнес-правила на основе трех констант статуса:
1.  **`ParcelStatusRegistered` ("registered"):** Посылка только что создана. На этом этапе пользователю **разрешено** изменять адрес доставки или полностью удалить посылку из системы.
2.  **`ParcelStatusSent` ("sent"):** Посылка находится в пути. Изменение адреса и удаление заблокированы логикой приложения.
3.  **`ParcelStatusDelivered` ("delivered"):** Посылка успешно доставлена адресату. Финальная стадия цепочки.

### Реализованный функционал в `parcel.go`:
*   **Регистрация посылки:** Добавление записи в БД со стартовым статусом `registered`. Номер строки (AUTOINCREMENT) становится трек-номером.
*   **Получение посылок клиента:** Выборка всех отправлений по переданному ID клиента.
*   **Обновление статуса:** Смена этапа доставки (`registered` -> `sent` -> `delivered`).
*   **Обновление адреса:** Корректировка места назначения (с валидацией статуса).
*   **Удаление посылки:** Очистка записи из таблицы (с валидацией статуса).

## Интеграционное тестирование (`parcel_test.go`)

Поскольку функции пакета напрямую взаимодействуют с СУБД, для проверки надежности написаны **интеграционные тесты**. Перед каждым тестом инициализируется реальное или временное подключение к файлу `tracker.db` для симуляции боевых условий.

Тесты проверяют:
*   Корректность CRUD-операций: запись данных в базу и их последующее безошибочное чтение (`Rows.Scan`).
*   Соблюдение бизнес-логики: невозможность изменить адрес или удалить посылку, если её статус отличается от `registered`.

##  Инструкция по запуску и тестированию

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com
   ```
2. Перейдите в папку проекта:
   ```bash
   cd название_папки_проекта
   ```
3. Запустите интеграционные тесты для проверки корректности SQL-запросов:
   ```bash
   go test -v .
   ```
4. Запустите демонстрационный сценарий в файле `main.go`:
   ```bash
   go run main.go
   ```
